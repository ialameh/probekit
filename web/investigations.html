Follow-up checks

    Related investigations

    Reports include labels, parameters, observations and your notes. They exclude raw result rows. Review before sharing.

    How to run queries and prepare exports

    Use a query tool approved by your organisation. Salesforce Developer Console has a Query Editor; set “Use Tooling API” to match the badge on each step. If your tool cannot export JSON or CSV, ask an administrator to provide the result files. Keep all selected columns and export every result page.

    Run each step with the displayed query. Accepting a result unlocks dependent steps. Replacing a prior result clears all later imports on that side. An unavailable step blocks its dependants but does not prevent independent checks.

    Queries can have result limits. Reaching a limit is flagged and does not establish that all matching records are present. Exports cannot independently prove the query was run, which org it came from, or whether it is current.

    Privacy and analysis limits

    Files and pasted results are processed locally in this tab, not uploaded or stored in browser storage. Clearing or reloading discards the investigation. Downloaded reports remain on your device. Standard hosting logs can record page visits, but not your pasted exports.

    Source and configuration columns marked for hashing are compared using SHA-256 fingerprints of exact exported content. This does not assess semantics. CSV has no type metadata: known boolean and numeric columns are normalised, but other CSV fields stay text. Prefer the same export format on both sides.

    The observations describe supplied evidence. Empty results, inactive flags and changed metadata do not by themselves establish absence, effective access, execution or root cause.
